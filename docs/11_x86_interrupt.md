# 中断异常处理

中断、异常、系统调用，这些都是控制权转移。
中断和系统调用可能切换任务，异常则不会。
但都要保存上下文、处理、恢复上下文，其中保存的上下文，根据是否切换任务有所不同。

相同的代码，出了支持中断异常，还可以实现：
- （在 ISR 内部）主动退出中断，类似于 exit(0)
- 主动任务切换，模拟发生一次任务切换，让出剩余的时间片
- 主动进入 ring3，模拟发生了一次异常，执行返回流程

## long-mode 硬件行为

wheel 工作在 64-bit mode，发生中断异常时，CPU 自动执行以下行为：
- 根据向量号查找 IDT，找出中断门类型，判断有误 IST
- 如果处在 ring3，则切换 TSS 里面记录的中断栈
- 这些寄存器按序入栈：SS/RSP/RFLAGS/CS/RIP/(err code)

## ISR 处理流程

当我们的 ISR 开始执行，说明发生了中断或异常，且 CPU 已经切换了栈，已经将一部分寄存器入栈。
根据不同的入口点，我们可以知道向量号。还有如下信息需要知道：
- 是否来自 ring3，可以检查 SS.CPL，这决定是否 swapgs，否则 thiscpu segment 取值错误
- 是否发生重入，可以检查 percpu-int-depth 变量判断
  如果未发生重入，说明当前处于任务的内核栈，主动切换到专用的中断栈

## IST 机制

中断异常可能重入。
如果不重入，如果来自 ring3，则自动切换栈到 tss->rsp0。如果已经处于 ring0 则保持在当前栈。
保持在 rsp0，如果多次重入，可能导致中断栈溢出，这很严重。

普通中断异常不会重入，因为软件可以屏蔽。软件无法屏蔽的异常不多：
- NMI，特殊硬件产生，不同设备的用途不同
- #DF，双重错误，例如在 ISR 里面又异常
- #PF，分页错误，例如在 ISR 里面访问了不合法的地址
- #MC，自检异常

已知这些异常自己不会重入，我们可以为这些 exception 指定专用的栈。
TSS 里面有 7 个 IST，IDT 中断门描述符里面记录 IST 编号，表示这个中断使用哪个 IST 栈。
