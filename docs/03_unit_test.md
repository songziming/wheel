# 单元测试

在 host 环境下运行 kernel 代码，可以用 gdb/asan/valgrind 这些工具辅助测试。
内核代码应测尽测，也包括 arch 模块中的代码（例如 mmu），生成覆盖率报告。

## 如何编译

所有内核的 C 代码都参与编译，编译成动态库 libwheel.so，相当于内核库。
要测试哪个函数，就在测试程序中调用哪个。

有些内核函数和符号与硬件有关，例如：
- 汇编代码中定义的（单元测试不含汇编代码）
- linker 脚本中定义的符号（单元测试不使用链接脚本）
- 设备驱动相关代码
这样的函数和符号需要在测试程序里 mock。
使用动态库的好处就是 mock 非常容易，测试程序里定义同名的符号，就会自动顶替内核库中的实现。

## 避免和 libc 同名的函数

内核代码是 freestanding 环境，不会链接 libc，可是单元测试程序会链接 libc。
如果内核里面有函数与 libc 函数同名，测试的时候会有冲突。

因此，我们将 `memcpy` 命名为 `kmemcpy`，将 `strcmp` 命名为 `kstrcmp`，阅读代码也更清晰。
